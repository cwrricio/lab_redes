FTP

File Transfer Protocol

Transferencia de arquivos, dois canais, modo passivo

RFC 959 (1985) | Porta 21 | TCP

Contexto

O protocolo mais antigo ainda em uso

FTP em 1985 (RFC 959)

Criado para transferir arquivos entre computadores. Foi o jeito padrao de publicar sites, softwares e dados por decadas.

Por que ainda importa

Aparece em hospedagem legada, equipamentos industriais e roteadores antigos. E um caso de estudo classico de seguranca em protocolos de rede.

FTP foi projetado para funcionar, nao para ser seguro. Toda a comunicacao, incluindo usuario e senha, vai em texto claro pela rede.

O mesmo RFC 959 de 1985 ainda descreve o protocolo usado hoje. Muito pouco mudou.

Conceito Central

Dois canais TCP independentes

A marca registrada do FTP e usar dois canais TCP separados para a mesma sessao.

Canal de Controle (porta 21)

Fica aberto a sessao toda. Aqui trafegam os comandos: USER, PASS, LIST, RETR, STOR, PASV, QUIT.

Canal de Dados (porta variavel)

Aberto e fechado a cada transferencia ou listagem. O conteudo do arquivo passa por aqui.

Os codigos de resposta sao numericos, como no HTTP: 220 pronto, 331 peca senha, 230 logado, 150 abrindo dados, 226 transferencia ok.
# Dialogo FTP capturado com curl -v

< 331 Please specify the password.
> PASS ftppass
< 230 Login successful.
> PWD

Modos de Transferencia

Modo Ativo vs. Modo Passivo

O canal de dados precisa ser estabelecido de alguma forma. Ha dois modos:

Modo Ativo (comando PORT)

O servidor abre conexao de volta para o cliente na porta que ele anunciar. Quebra com NAT e firewall do lado do cliente. Quase nao funciona mais.

Modo Passivo (comando PASV)

O servidor abre uma porta e informa o cliente. O cliente e quem conecta. Funciona atraves de NAT e firewall. E o modo usado hoje.

No nosso lab fixamos a faixa passiva em 21100-21110 para conseguir mapear no Docker. Sem isso, o servidor sortearia qualquer porta alta e o NAT nao saberia encaminhar.
# Modo Ativo (problematico com NAT):
# Servidor conecta DE VOLTA ao cliente
Client:  PORT 192,168,1,5,20,50
Server:  (conecta em 192.168.1.5:5170)

# Modo Passivo (funciona com NAT):
Client:  PASV
Server:  227 Entering Passive Mode
         (127,0,0,1,82,113)
         # porta = 82*256 + 113 = 21105

Client:  (conecta em 127.0.0.1:21105)

# Nosso lab: faixa fixa 21100-21110
# docker-compose.yml:
ports:
  - "21:21"
  - "21100-21110:21100-21110"

Rede

Porta 21 e a faixa passiva

  • Porta 21 e a porta well-known do canal de controle (IANA). Portas 0-1023 sao reservadas a servicos padrao.
  • O canal de dados usa uma porta negociada: no modo passivo, o servidor escolhe e informa o cliente via PASV.
  • Para funcionar com Docker e NAT, a faixa passiva precisa ser fixa e mapeada.
  • O FTP usa TCP nos dois canais: precisa de entrega confiavel e ordenada para os arquivos.
Por que dois canais e nao um? Design original de 1985: separar comandos de dados permite que o controle permita continuar enquanto o arquivo transfere. Mas complica firewalls e NAT.
# Portas do laboratorio
docker compose port ftp 21
0.0.0.0:21

# Canal de controle: sempre 21
# Canal de dados: faixa 21100-21110
# (negociado via PASV)

# Ver o servidor escutando (dentro do container):

Autenticacao

Usuario e senha em texto claro

A autenticacao no FTP e feita pelos comandos USER e PASS no canal de controle.

Usuario, senha e conteudo dos arquivos viajam em TEXTO CLARO. Qualquer pessoa na mesma rede captura com um sniffer. No Wireshark, filtre por 'ftp' e voce le USER e PASS diretamente.
Nao ha como melhorar isso no FTP puro. Para criptografia, e preciso trocar o protocolo: FTPS ou SFTP.

Filtro Wireshark: ftp (ver comandos) | ftp-data (ver conteudo dos arquivos)

Transferencia

Upload e download de arquivos

Os principais comandos de transferencia no protocolo FTP:

ComandoDirecaoDescricao
RETR (retrieve)Remoto para localDownload de arquivo
STOR (store)Local para remotoUpload de arquivo
LIST-Lista o diretorio
DELE-Remove arquivo no servidor
MKD-Cria diretorio
PWD-Diretorio atual
Cada transferencia abre um novo canal de dados, transfere e fecha. O canal de controle permanece aberto.
# Upload: LOCAL para REMOTO
curl --ftp-pasv \
  -T /tmp/arquivo.txt \
  ftp://ftpuser:ftppass@127.0.0.1/arquivo.txt

# Download: REMOTO para LOCAL
curl --ftp-pasv \
  ftp://ftpuser:ftppass@127.0.0.1/exemplo.txt \
  -o /tmp/baixado.txt

# Listagem
curl --ftp-pasv \
  ftp://ftpuser:ftppass@127.0.0.1/

# Via FileZilla:
# Host: 127.0.0.1  Porta: 21
# Usuario: ftpuser  Senha: ftppass
# Modo: Passivo (sempre)

Seguranca no Servidor

Permissoes e isolamento (chroot)

O vsftpd oferece mecanismos de isolamento para limitar o que um usuario pode acessar.

chroot_local_user

Prende o usuario no proprio diretorio home. Ele nao ve o resto do sistema de arquivos. Uma jaula: se a conta vazar, o estrago fica contido.

local_umask=022

Arquivos enviados nascem com permissao 644 (dono escreve, demais so leem). Controla quem pode ler os arquivos enviados.

O chroot nao substitui a criptografia. O usuario fica preso no diretorio, mas as credenciais e os arquivos ainda viajam em claro pela rede.
# vsftpd.conf (nosso lab)
chroot_local_user=YES
allow_writeable_chroot=YES
local_umask=022

# Resultado: usuario preso no home
ftpuser@servidor:~$ cd /etc
550 Failed to change directory.

# Arquivos enviados: permissao 644
ls -la /home/ftpuser/
-rw-r--r-- 1 ftpuser ftpuser 59 exemplo.txt
-rw-r--r-- 1 ftpuser ftpuser 57 upload.txt
#           ^ 644: dono rw, outros r

# Verificar dentro do container:
docker compose exec ftp ls -la /home/ftpuser

Alternativas Seguras

FTPS e SFTP: como resolver o texto claro

O FTP puro nao tem criptografia. Ha duas solucoes, com arquiteturas bem diferentes:

FTPS (FTP + TLS)

FTP tradicional com uma camada TLS sobre os dois canais. Ainda usa porta 21 e a faixa passiva. Mais complexo de configurar em firewall. Requer certificado TLS. (ssl_enable=YES no vsftpd)

SFTP (SSH File Transfer Protocol)

Nao e FTP. E um subsistema do SSH. Um unico canal cifrado na porta 22. Muito mais simples de configurar. Ja demonstrado no lab de SSH.

SFTP e FTPS sao frequentemente confundidos. Nomes parecidos, arquiteturas completamente diferentes.
# FTPS: FTP com TLS
# (vsftpd.conf)
ssl_enable=YES
rsa_cert_file=/etc/ssl/cert.pem
rsa_private_key_file=/etc/ssl/key.pem
# ainda usa porta 21 + faixa passiva

# SFTP: subsistema do SSH
# (ja disponivel no lab de SSH)
sftp -F client/ssh_config lab

sftp> ls
sftp> put /tmp/arquivo.txt
sftp> get remoto.txt /tmp/
sftp> bye

# Comparativo:
# FTP:  porta 21 + 21100-21110, texto claro
# FTPS: porta 21 + 21100-21110, cifrado com TLS
# SFTP: porta 22 apenas, cifrado com SSH

Comparativo

FTP, FTPS e SFTP lado a lado

Protocolo Porta(s) Canais Cifrado Senha na rede Recomendado hoje
FTP 21 + dados 2 canais TCP Nao Texto claro Nao
FTPS 21 + dados 2 canais TCP + TLS Sim Cifrada Complexo
SFTP 22 1 canal SSH Sim Cifrada Sim
SSH/SCP 22 1 canal SSH Sim Cifrada Sim
Para novos sistemas, SFTP (sobre SSH) e a escolha mais simples e segura. Um canal, uma porta, sem complicacao de firewall.

O que acontece numa sessao FTP

Passo Comando (cliente) Resposta (servidor) Canal
Conectar (TCP connect) 220 Bem-vindo Controle
Usuario USER ftpuser 331 Informe a senha Controle
Senha PASS ftppass 230 Login ok Controle
Solicitar passivo PASV 227 Porta 21105 Controle

Enviar STOR novo.txt 150 Abrindo... / 226 OK Dados (nova porta)
Sair QUIT 221 Ate logo Controle

FTP no Wireshark

O FTP e o protocolo mais didatico para analisar no Wireshark: tudo e legivel.

Limitacoes do Experimento

O que ficou de fora

  • FTP em texto claro de proposito: mantivemos para capturar a senha no Wireshark e demonstrar o problema. Em producao, use SFTP ou FTPS.
  • Tudo em loopback (127.0.0.1): em um cenario real, cliente e servidor estao em maquinas diferentes. O pasv_address precisaria ser o IP real do host.
  • Sem TLS (FTPS): configurar FTPS exige certificado e ajustes de firewall para os dois canais. Ficou fora do escopo.
  • Sem rate limiting nem cotas de disco: itens de producao nao implementados no lab.
  • Usuario unico: em um servidor real, cada usuario teria seu proprio chroot e permissoes especificas.

Conclusao

FTP: dois canais, texto claro, legado.

Dois canais

Canal de controle na porta 21 e canal de dados na faixa passiva. Mais complexo que protocolos modernos.

Modo passivo

PASV resolve o problema de NAT e firewall. E o modo necessario para funcionar na internet moderna.

Use SFTP hoje

Para transferencia segura, SFTP (sobre SSH) e a escolha correta. Um canal, cifrado, sem complexidade.
